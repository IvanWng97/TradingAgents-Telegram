# rendering/ — data → user-visible output

Pure transforms from data structures to wire format. Output is a string/bytes meant for Telegram or Telegraph.

See root `CLAUDE.md` Invariant #4 for the MarkdownV2/HTML carve-out — this subpackage owns the HTML side.

`email_client.py` mirrors `telegraph_client.py`'s shape — a single file owning both the HTML template build AND the network send (in `asyncio.to_thread`). They live in `rendering/` because their output is "string/bytes meant for external delivery" — same membership rule as the existing Telegraph publish path. Email delivery is **opt-in per user** (digest schema's `email` field) and **mirror-only**: failures NEVER break the Telegram path (the email_client swallows internally; `run_user_digest` also wraps the call in another try/except for defense in depth). `is_email_configured()` is the env-var gate (`RESEND_API_KEY` + `RESEND_FROM` both required). The HTML body uses inline-style attributes only — Gmail and Outlook both strip `<style>` blocks and ignore `<link rel=stylesheet>`. Per-ticker `.md` attachments are built lazily via `load_historical_state` (the same disk path `/history` reads), keeping email building decoupled from the digest's `status` dict (which only carries the signal + Telegraph URL). A missing log file (ephemeral Docker FS without persistent `TRADINGAGENTS_RESULTS_DIR`) skips just that ticker's attachment with a log line, never the whole email.

`send_digest_email` returns `EmailSendResult(ok, recipient, message_id, error)` (frozen dataclass). `ok=True` only on Resend-accepted send with a message id; otherwise `error` is `"not_configured"` / `"malformed_response"` / `type(e).__name__`. Never raises — Telegram-mirror invariant unchanged. The footer-rendering caller lives in `handlers/CLAUDE.md`.

**Membership-rule inflection point at N=3 delivery channels.** This subpackage was originally "string/bytes meant for Telegram or Telegraph" (PR #56 origin). PR #73 broadened it to "string/bytes meant for external delivery" so `email_client.py` fits cleanly. Safe at N=2. If a third delivery channel ever lands (Slack webhook, Discord, SMS, etc.), the new author MUST consciously re-evaluate whether `rendering/` is still the right home or whether a `delivery/` subpackage is warranted — otherwise the rule silently degrades to a catch-all. The decision needs to be intentional, not invisible. Until then, two delivery clients side-by-side (telegraph_client + email_client) is the documented shape.

## Key contracts

- **Caption rendering (HTML).** `format_short_message` builds the post-analysis caption as **HTML**: signal emoji (`BUY` 🟢, `OVERWEIGHT` 🟩, `HOLD` 🟡, `UNDERWEIGHT` 🟥, `SELL` 🔴), `<b>ticker</b>`, `<b>signal verb</b>`, summary wrapped in `<blockquote expandable>`, then `<i>Generated …</i>` + `<i>via provider · …</i>`. Summary sources from **`final_trade_decision`** (post-risk-debate synthesis — matches the badge by construction) via `formatters.caption_summary`, which prefers the **`**Executive Summary**` section** body when present (the structured TL;DR with concrete price levels + stops + re-entry zones) and falls back to a strip-header + 700-char clip for older or non-conforming outputs. Both `**Executive Summary**:` and `**Executive Summary:**` header variants are accepted; section terminates at the next `\n\n**` paragraph header. **No inline Telegraph link** — `_full_report_keyboard(ticker, date, telegraph_url)` emits a two-button row (📰 Instant View URL → Telegraph IV, may truncate sections under the 40K budget · 📥 Download Full Report callback → unbounded `.md`, all 7 sections). Label asymmetry advertises the completeness guarantee. On publish failure (`telegraph_url=None`), the IV button is omitted AND the caption surfaces `⚠️ Instant View unavailable`. Summary runs through `markdown_to_telegram_html`; tables and `<img>` are dropped by the sanitizer to fit the 1024-char caption budget.
- **Telegraph body — 7-section packer.** `format_analysis_result_markdown` packs sections from `final_state` in priority order: Final Trading Decision → Trader's Recommendation → Research Manager Synthesis (`investment_plan`) → Market Analysis → Fundamentals → News → Sentiment. Each prefixed `## Title\n\n`. Section content runs through `_normalize_nested_bullets` so LLM-emitted col-0 sub-bullets directly under a numbered item get padded to 4-space indent (Python-Markdown requires this for `<ol><li><ul>` nesting; without it, sub-bullets render as flat siblings on Telegraph IV). State machine resets on a non-blank, non-bullet, non-numbered line so the pad only fires for the common LLM mistake. Packer converts via `markdown.markdown(extensions=["tables"])`; if HTML exceeds the 40K budget, drops the lowest-priority section and re-converts. Table-heavy sections (market, fundamentals) are usual drops. Dropped content survives via the `.md` document attachment. Optional `> Generated <ts> · <config>` blockquote prepends when supplied so shared URLs self-document.
- **Telegraph publishing — offloaded + resilient + edit-in-place.** `telegraph_client.publish_to_telegraph(title, content, edit_path=None)` wraps the SDK's blocking calls in `asyncio.to_thread`. Title comes from `key.telegraph_title(ticker)` at both publish call sites so different configs on the same ticker produce different URLs (no Telegraph `-2`/`-3` collision suffix). Four resilience layers:
  1. **`edit_path` enables in-place updates** (set by `/refresh` from the cached `telegraph_url`) — `edit_page` first so the URL stays stable. **Two failure modes diverge:** *transient* edit errors get one retry then return None (does **not** fall through to `create_page` — that would leak a new URL and defeat the fix); the cache-hygiene gate then skips the store so the next tap retries cleanly. *Non-transient* edit failures (page deleted, auth drift, oversized) fall through to `create_page` — fresh URL is acceptable degradation when the edit-target is broken.
  2. **One retry with 1s backoff on transient network errors** — applied to both `edit_page` and `create_page` via `_call_with_transient_retry`. `_TRANSIENT_NET_ERRORS = (ConnectionError, Timeout)`. API-level `TelegraphException` (content/auth/`CONTENT_TOO_BIG`) skips retry — re-running would fail identically.
  3. **Failure log records input/cleaned HTML sizes + exception class** so triage doesn't require re-instrumenting.
  4. **HTML budget 40,000** (`formatters._TELEGRAPH_HTML_BUDGET`, lowered from 64,000) — Telegraph's 65,536 cap is on their internal JSON Node tree, which the SDK inflates 25–40% over the raw HTML we submit. Lower budget lets the packer drop sections before Telegraph rejects.

  `_path_from_telegraph_url(url)` returns None for non-Telegraph URLs so callers fall back to `create_page` instead of feeding garbage to `edit_page`.
- **Two HTML sanitization stages, distinct tag vocabularies.** Captions and Telegraph pages target different allowed-tag sets, so two separate sanitizers run on different surfaces; they are NOT interchangeable. (a) `formatters.sanitize_html_for_telegram` (stdlib `HTMLParser` + whitelist) whitelists Telegram's caption tag set (`<b>`, `<i>`, `<a href="">`, `<blockquote expandable>`, etc.), drops tables/images, and balances bare-anchor close tags via a depth counter. Used by `markdown_to_telegram_html` for caption surfaces (`format_short_message`, `/history` republish, digest header). (b) `telegraph_client.sanitize_html_for_telegraph` (BeautifulSoup + tag-map + table→`<ul>` rewrite) rewrites for Telegraph's tag set. Used at publish time on the markdown-rendered body. Don't merge these — different upstream tag vocabularies, different transform rules.
- **finviz cache-busting**: `chart.py:finviz_chart_url` appends `&_=<unix_ts>` so Telegram's CDN doesn't serve a stale cached photo. Defaults (`chart_type="c"` candle, `period="d"` daily, `size="l"` large, `ta=1` indicators) are all used at the single call site; no per-user customization. Param values are not validated — an invalid value silently produces a broken chart URL that fails at `send_photo`.
- **`_normalize_nested_bullets` state machine resets on pre-indented bullets (`formatters.py:300-303`).** `_is_unindented_bullet` only matches col-0 `- `/`* ` lines. A mixed-indent LLM output where some sub-bullets are `  - already indented` and others are `- col-0` causes the state machine to flip `inside_ol = False` on the indented one, and all subsequent col-0 bullets lose their auto-pad. Diagnostic: bullets render as flat siblings on Telegraph IV after the first pre-indented item in a numbered-list section.
- **`_extract_executive_summary` terminates on `\n\n**`, NOT `\n\n##` (`formatters.py:497`).** Non-conforming LLM output that uses `## Subsection` instead of `**Bold**` subsection headers will overshoot the summary boundary; only the 700-char clip in `extract_summary` (`formatters.py:528`) saves the caption. 700-char budget is sized for raw markdown — HTML escape + `<blockquote expandable>` overhead (~26 chars) push the final HTML past 700; comment acknowledges "~10-15% bloat" as an estimate, not a guarantee.
- **`_build_header` `---` separator is load-bearing (`formatters.py:287`).** Without the horizontal rule between the generated-by blockquote and the body, a body section starting with `> ` (a quote) silently fuses with the header blockquote in Python-Markdown's parser. Removing the `---` "for cosmetics" will silently break section boundaries.
- **`_convert_tables_to_lists` joins `<th>` body-row cells as headers (`telegraph_client.py:45-48`).** `<thead>` row cells become list-section labels, but body rows that mix `<th>` (row headers) with `<td>` (data) use `get_text` on all cells alike — row-header tables (common in LLM-generated fundamentals comparisons) produce misleading list items where the row-label becomes a data field.
- **`escape_md_v2_url` is ONLY safe inside `[text](url)` link targets (`formatters.py:11-18`).** Escapes only `\` and `)` — the carve-out from full `escape_markdown(version=2)` exists because the full escaper would double-escape characters legal inside a `()` link target. Using `escape_md_v2_url` on raw URL text outside a link will produce unescaped MarkdownV2 specials and a `Bad Request: can't parse entities`.
- **`_TRANSIENT_NET_ERRORS = ()` if `requests` is not importable (`telegraph_client.py:79-88`).** The `try/except ImportError` is guarded with a `pragma: no cover — requests is a transitive dep` comment. In practice `requests` is always present (the `telegraph` SDK depends on it). But if that dependency chain ever changes, `_call_with_transient_retry` silently stops retrying with no log. Watch on `telegraph` SDK upgrades.
