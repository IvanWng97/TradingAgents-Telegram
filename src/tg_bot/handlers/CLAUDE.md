# handlers/ — PTB handler dispatch surfaces

Registers PTB handlers (CommandHandler, CallbackQueryHandler, TypeHandler) OR is the direct callback implementation for a registered handler (e.g. `pickers.py` builds the keyboards that handlers return). NOT "anything called by a handler" — that's too broad and creates junk-drawer drift.

See root `CLAUDE.md` for the request lifecycle, state ownership table, and Invariants #2, #3, #5, #7 — all relevant here. Storage singletons (`watchlist_storage`, `user_config_storage`) are imported from `tg_bot.storage`; never construct your own — see `storage/CLAUDE.md` for the full singleton contracts.

## Commands

User-facing command behavior lives in `README.md` (Commands table) and `commands.py` (implementation). Slash-menu copy is `app.py:BOT_COMMANDS`, registered via `set_my_commands` in `_post_init` (which also stamps `bot_data["start_time"]` for `/status` uptime).

Bot-internal mechanics worth knowing that aren't in README:

- **Two-form pattern.** `/add`, `/del`, `/refresh` all support both bulk-arg form (`/del NVDA AAPL`) and no-arg form (inline picker). `/add` (no args) uses `ForceReply` and matches the prompt verbatim against `update.message.reply_to_message.text` so `add_via_reply` only fires on real replies.
- **`/list` is read-only; `/watch` is the picker.** Until PR #56 they were aliases (both opened the picker). Now `/list` produces a MarkdownV2 text view: title + optional digest header + a ticker grid inside a triple-backtick pre block (so spaces inside are guaranteed monospace, fixing the alignment wobble that inline-codespan grids inherit). Grid cells pad to `max(len(t)) + 2`; column count adapts to fit ~36 chars on mobile viewports (4 cols for short US tickers, drops to 2 when a long ticker like `RELIANCE.NS` lands in the watchlist, 1 col for pathological 20+ char tickers). 🔔 enrollment markers live in the header section (an indented `→ T1, T2` line listing enrolled tickers), never in the grid — inline markers would break the monospace padding. Empty watchlist short-circuits to a `/add` nudge. No callbacks, no chat_data, no inline keyboard — pure storage read + format + reply. The digest-enrolment intersection is computed by `user_config_storage.get_enrolled_tickers` (shared with `run_user_digest` — that method is the single canonical evaluator for "what tickers does this user's digest fire today"). The helper `_digest_enrolled_set` wraps it to add a `None` sentinel for "digest off entirely" (different footer copy from "digest on but enrolled set is empty"), since the storage method deliberately doesn't gate on `enabled`.
- **Watch + Refresh share the picker.** Both `/watch` (no-args) and `/refresh` (no-args) render via `build_watchlist_response(..., mode=...)`; the only differences are header copy, Done-button label (`✅ Done (N)` vs `🔄 Refresh (N)`), and Done-tap behavior (refresh threads `force_refresh=True` into the runner so it bypasses the cache-hit short-circuit but reuses the prior `telegraph_url` for `edit_page` URL stability — NOT a pre-invalidation). `chat_data["watch_mode"]` carries the choice through every re-render. See Invariant #7 (root).
- **`/email` configures the digest email mirror (opt-in).** Sub-commands: bare `/email` shows current setting + help; `/email foo@bar.com` validates + saves; `/email off` clears; `/email test` sends a synthetic test email. All responses MarkdownV2 (Invariant #4). No ForceReply flow — single-token arg parsing keeps the command simple. Multi-arg input (`/email foo@bar.com extra`) is rejected to avoid swallowing typos. The actual send wiring lives in `run_user_digest` after the summary edit (mirror, not separate channel); `/email test` calls `send_digest_email` directly with a synthetic one-ticker payload so operators can verify Resend wiring without waiting for a real digest fire.
- **Email-status footer on the digest summary.** When the user has opted in, `run_user_digest` issues a SECOND `edit_message_text` after the primary summary edit, appending a one-line italic footer reflecting the outcome of the mirror: `📧 Sent to <addr>` (success), `📧 Email failed — check logs` (Resend exception or malformed response), or `📧 Email opt-in but server not configured` (opt-in but `RESEND_API_KEY`/`RESEND_FROM` missing in `.env`). No footer at all for non-opted-in users — the existing Telegram-only UX is preserved exactly. Two-edit shape is load-bearing: the primary summary edit is unaffected by Resend latency or failure, so the email-mirror invariant (Telegram never blocked by email) extends to the rendering layer. The second edit is best-effort — a failure to append the footer logs INFO and leaves the primary summary + email send unaffected. Footer text built by `_build_email_status_line(email_to, result)`; rendered shape is `<i>📧 …</i>` to match the existing tally/skipped-footnote pattern in `_format_digest_summary`. See Invariant #4 (HTML parse_mode) — recipient is `html.escape`'d into the line.
- **`/status` shows the active env-derived LLM config.** Provider / deep / quick / rounds / effort all flow from `build_config()` (see `pipeline/CLAUDE.md`); effort is resolved via `EFFORT_KEY_BY_PROVIDER[provider]` so the per-provider key (`openai_reasoning_effort` / `anthropic_effort` / `google_thinking_level`) maps correctly. No `/config` picker exists — operators edit `.env` and restart to switch.
- **`/history`** parses `<ticker> [YYYY-MM-DD]` — date arg must round-trip through `date.fromisoformat`. Reads tradingagents' on-disk JSON logs at `<results_dir>/<TICKER>/TradingAgentsStrategy_logs/full_states_log_<date>.json`. `← Back` round-trip nav via `hist_back:` prefix. See root `CLAUDE.md` for `history.normalize_ticker` path-traversal guard.

## Key contracts

- **Callback dispatch** is prefix-based: `multi:`, `wsel:` (bulk select-all/clear), `wpage:` (pagination prev/next/noop), `runall:`, `digest:` (digest picker — sub-actions `hour:HH`, `tz:<IANA>`, `tzpick`, `hourpick`, `off`, `run`, `tickerpick`, `tt:<TICKER>`, `ttall`, `ttclear`, `ttpage:{prev,next,noop}`), `digest_cancel:<msg_id>` (abort an in-flight fan-out), `del:`, `cancel:`, `cancel_analysis:`, `hist:`, `hist_t:`, `hist_back:`, `getmd:<TICKER>:<DATE>` (deliver the full `.md` archival report on demand). Order matters where prefixes overlap (`cancel_analysis:` is checked before `cancel:`, `digest_cancel:` before `digest:`). Stay under Telegram's 64-byte `callback_data` limit.
- **Reply-driven `/add`.** `commands.ADD_PROMPT` is matched verbatim against `update.message.reply_to_message.text` so `add_via_reply` only fires on replies to our actual prompt, not random replies to bot messages.
- **Watchlist UX (paginated select-mode, shared by `/watch` and `/refresh`).** Both render the same paginated toggle keyboard via `build_watchlist_response(..., mode=...)` (`WATCHLIST_PAGE_SIZE = 9`, 3×3). Selection state: `chat_data["watch_selection"]: set[str]` persists across pages; `chat_data["watch_page"]: int` resets on each fresh invocation. **`chat_data["watch_mode"]` is `"watch"` or `"refresh"`** — set by the entry command, threaded through every re-render handler, `pop`'d by `_handle_done`. Refresh mode differs only in header copy, Done button label (`🔄 Refresh (N)` vs `✅ Done (N)`), and `_handle_done` threading `force_refresh=True` into each `_run_analysis_for_ticker`. **`force_refresh=True` does NOT pre-invalidate the cache** — instead the runner reads the prior cached `telegraph_url` (for `edit_page` URL stability), skips the cache-hit short-circuit, and overwrites the entry with the fresh result. Pre-invalidation would drop the URL before we could reuse it. Bulk actions `wsel:all` / `wsel:clear` operate on the entire watchlist. `runall:go` (Done) dispatches: 1 ticker → direct call; 2+ → `asyncio.gather(*runs)` for parallel.
- **Cancel registry.** `chat_data["analysis_cancels"]` is `{run_id: {"cancel_event": threading.Event, "async_event": asyncio.Event, "message_id": int|None}}` — populated by `_run_analysis_for_ticker` on entry (UUID `run_id` chosen before `send_photo`, `message_id` backfilled after), popped in `finally`. The Cancel button's `cancel_analysis:<run_id>` callback looks up the entry and `set()`s both events (`cancel_event` aborts in-flight LLM calls via the progress callback; `async_event` wakes a queued semaphore wait). Three race-close checks in the analysis path (post-`to_thread`, post-Telegraph publish, plus the in-pipeline raise) ensure a late tap still discards the result instead of overwriting "Cancelling…" with a success caption. See Invariant #5 (root) for the digest variant's diverging race-close pattern.
- **Digest schedule** is the source of truth in `user_config.json`; PTB's `JobQueue.run_daily` is just an in-memory schedule reconstructed from storage at every `_post_init`. `register_digest_job(application, user_id, digest)` cancels any existing job under name `digest:<user_id>` and re-creates with `time=dt_time(hour_local, tzinfo=ZoneInfo(tz))`, so an hour or tz change replaces the schedule rather than duplicating it. DST is handled by `ZoneInfo`. JobQueue callback routes through `run_user_digest`, which calls `user_config_storage.get_enrolled_tickers(user_id, watchlist)` to compute "what fires today" — that method is the single source of truth for the legacy-fallback + intersection semantics (also used by `/list`'s text view via `_digest_enrolled_set`). Empty result → reminder message, no fan-out. After the filter intersection a **per-ticker market-calendar gate** (`market_calendar.is_market_open_for(ticker, date.today())`) drops closed-market tickers — if every ticker's market is closed today, the whole fan-out short-circuits with a one-line "Markets closed today" heads-up (no header, no Cancel button, no LLM calls); partial closures render a `⚫️ Skipped (markets closed): X, Y` footnote in both progress and summary views via the optional `skipped_closed` arg threaded through `_format_digest_progress` / `_format_digest_summary`. Sends a header (with `❌ Cancel digest` button), fans out via `_analyze_one_for_digest` (each ticker holds the global `_run_semaphore`, so the digest interleaves naturally with manual `/watch` runs), edits the header progressively as steps fire (single-flight **trampolining** throttle at `_DIGEST_PROGRESS_INTERVAL`: a state change arriving while an edit is mid-HTTP sets `pending_rerender` and the in-flight render loops back to repaint once the edit returns — required so a cache-hit ticker's instant completion doesn't starve a concurrent fresh ticker's `Starting…` row), and replaces it with a summary at completion. On `Forbidden` (user blocked the bot) the digest auto-disables and the JobQueue job is cancelled. The cancel button sets a shared `cancel_event` (threading) so in-flight tickers raise `CancelledByUserError` at the next LLM-call boundary, and `Task.cancel()`s pending tickers so they unwind without acquiring a slot. `▶ Run now` is guarded by `chat_data["digest_running:<user_id>"]` so a re-tap during an active fan-out doesn't spawn N parallel digests. Backward compat: legacy saves with `tickers` absent (key missing) are treated as "all watchlist" at fan-out time (handled inside `get_enrolled_tickers`) AND backfilled to the actual watchlist on first `_post_init` startup, after which every enabled digest has the field present. Picker-internal reads in `digest.py` deliberately do NOT use this method — they show the user's *currently saved* tickers during editing, where a fallback would mislead ("0/12 tickers" is the right pre-pick state, not "all enrolled").
- **Full `.md` archival report — opt-in via `📥 Download .md` button.** The photo+caption from `/watch` (fresh + cache-hit) and `/history` carries a `_full_report_keyboard(ticker, date_iso)` inline button. Tapping fires `getmd:<TICKER>:<DATE>` → `_handle_get_full_md` → `load_historical_state(ticker, date_str)` reads `<TRADINGAGENTS_RESULTS_DIR>/<TICKER>/TradingAgentsStrategy_logs/full_states_log_<date>.json` (durable, kept forever — NOT `result_cache`, which is same-day only and would 404 for older photos) → `format_full_md_report` builds the unbounded `.md` (all 7 sections, no cap) → `bot.send_document(InputFile(BytesIO(md.encode()), filename="<TICKER>_<YYYY-MM-DD>.md"), reply_to_message_id=query.message.message_id, allow_sending_without_reply=True, disable_notification=True)` posts it as a reply to the photo. **`date_iso` is always the local date** (`date.today().isoformat()` or `today_iso` from the cache lookup key) — matches tradingagents' log filename convention; using the UTC `generated_at` would 404 for late-night runs in negative-UTC zones (e.g. 23:00 PDT → 06:00 UTC next day). Fallback when the log is missing (ephemeral Docker FS without `TRADINGAGENTS_RESULTS_DIR` persistence): plain reply `📥 Markdown report unavailable for <T> on <D>.` instead of a silent miss. Multi-tap = multi-doc (intentionally not deduped — no callback state to maintain).
- **Callback dispatch is a textual if-elif chain (`callbacks.py:699-748`), not PTB handler priority.** The two documented "order matters" pairs (`cancel_analysis:` before `cancel:`, `digest_cancel:` before `digest:`) are enforced solely by their position in this chain. Adding a new prefix that string-prefix-overlaps an existing one (e.g. `digests:` or `cancel_now:`) silently misroutes if inserted in the wrong order. Review the chain position before inserting any new prefix.
- **`send_photo` failure returns `"completed"`, not `"failed"` (`analysis_runner.py:405-420`).** Intentional — a Telegram-side network blip shouldn't surface as analysis failure in the queue-done summary. But the asymmetry is invisible: a failed-to-deliver run looks identical to a delivered one in tally counts. Adding new error reporting must look at the log layer, not the return code.
- **Picker `chat_data` cleanup happens at command entry, NOT on cancel.** `_handle_cancel` (callbacks.py) only pops `watch_mode`/`watch_selection`/`watch_page` when `what == "watch"` (i.e., the ❌ Cancel inside the picker is tapped). If the user deletes the picker message instead, stale state persists indefinitely; the next `/watch` or `/refresh` invocation overwrites all three keys at the entry point — that's the actual cleanup. Don't rely on cancel for cleanup.
- **`_handle_done` delays `chat_data` pop until after LLM precheck.** If the precheck fails (no `TRADINGAGENTS_LLM_PROVIDER` set, or the provider's API key is missing in `.env`), state is preserved so the user can re-run after fixing `.env` and restarting. The precheck is `check_llm_configured()` from `pipeline/analysis.py` — no-arg form reads the current `build_config()`. Side effect: a stale picker message can still fire `runall:go` from a keyboard replay, and the mode/selection popped at the new entry will be whatever's in state — not necessarily what the visible keyboard implies. If keyboard-replay correctness matters for a new flow, add a message-id check.
- **Digest cancel registry is keyed by `message_id` (int), NOT `run_id` (UUID) (`analysis_runner.py:1097-1101`).** Diverges from `analysis_cancels` which uses UUIDs. The `digest_cancel:<msg_id>` callback payload is an integer. Telegram's message-id pool is per-chat and effectively unique within sane time horizons, so collisions don't happen in practice, but the asymmetry is worth pinning when debugging cancel-registry confusion.
- **`_wrapped` catches both `CancelledByUserError` AND `asyncio.CancelledError` in the same clause (`analysis_runner.py:1198`).** First fires from the LangChain callback (in-flight LLM abort); second fires when `Task.cancel()` is called on a pending ticker (pre-semaphore-acquire abort). Both set `status[ticker] = "cancelled"`. Don't conflate them if you add retry logic — a `CancelledError` is externally driven, `CancelledByUserError` is the user's button.
- **Trampolining throttle (`analysis_runner.py:1108-1203`) is loop-thread-local-safe only.** `_render`, `_on_step`, `_wrapped` mutate `status`/`pending_rerender` at `await` boundaries on the single asyncio loop. The pattern is safe today because no `asyncio.to_thread` writes status. If a future change adds thread-offload to the status path (e.g. `loop.call_soon_threadsafe`-based `_on_step`), `pending_rerender` becomes a TOCTOU race and the trampoline loop at `1131-1171` no longer closes it. Add an `asyncio.Lock` before introducing thread-offload here.
- **`_try_acquire_nonblocking` reads CPython-private `sem._value` / `sem._waiters` (`analysis_runner.py:153-176`).** Mentioned in root `CLAUDE.md` Known Limitations as a watch-item on Python version bumps. The single-event-loop safety reasoning: `_value -= 1` cannot race because asyncio coroutines don't preempt between the `if not locked()` check and the decrement — only true on the single-threaded event loop. If `_try_acquire_nonblocking` ever gets called from a thread, that invariant breaks.
- **`ForceReply` text match is strict equality on the full string (`commands.py:160`).** `(replied.text or "") != ADD_PROMPT` — exact bytes. Trailing whitespace, BOM, or a future edit to `ADD_PROMPT` (`commands.py:45`) with stray characters silently disables `add_via_reply` with no error. Also: `selective=True` means the prompt only shows for the invoking user; in a group with multiple allowed users, a second user's `/add` won't pre-fill.
- **`/history` republish always creates a new Telegraph page (`pickers.py:259`).** `build_history_response` calls `publish_to_telegraph(title, html)` with no `edit_path` — same ticker+date via `/history` accumulates Telegraph pages (`-2`, `-3` suffixes after the first). The `Historical` token in the title reduces collisions with `/watch` URLs but doesn't dedupe. If Telegraph ever rate-limits per-account by page count, this path hits it first.
