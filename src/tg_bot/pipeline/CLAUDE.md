# pipeline/ — LLM execution hot path

In the hot path between "user taps ticker" and "LLM result ready." Modules that build/run/cache LangGraph propagation.

See root `CLAUDE.md` for the request lifecycle (lines 66–83), state ownership table, and Invariants #1, #2, #5, #6 — all relevant here.

## Key contracts

- **`TRADINGAGENTS_AVAILABLE`** flag gates analysis; bot still loads if tradingagents fails to import.
- **`.env` is the single source of truth for the active LLM config.** `build_config()` returns a fresh copy of tradingagents' `DEFAULT_CONFIG` (already overlaid by upstream `_apply_env_overrides` at lib import for provider / deep / quick / rounds) with our local `_apply_local_effort_overlay` applied for the three per-provider effort knobs upstream doesn't expose: `TRADINGAGENTS_OPENAI_REASONING_EFFORT` / `TRADINGAGENTS_ANTHROPIC_EFFORT` / `TRADINGAGENTS_GOOGLE_THINKING_LEVEL`. The env-var names are derived from `EFFORT_KEY_BY_PROVIDER.values()` so adding a provider's effort knob there auto-extends the overlay. `build_config()` returns a **fresh dict per call** — callers may mutate without poisoning the next call. `get_current_config_key()` is a thin convenience that wraps `AnalysisConfigKey.from_config(build_config())`.
- **`AnalysisConfigKey` is the source of truth for config identity.** Frozen dataclass `(provider, deep, quick, rounds, effort)` emitting three shapes: `slug()` → cache dir (`provider__deep__quick[__r{n}][__e{level}]`), `caption()` → caption "via" line (`provider · deep/quick [· r{n}] [· e={level}]`), `telegraph_title(ticker)` → page title (`<TICKER> Analysis · <caption>`). Constructed per request from `build_config()` and threaded into cache, caption, Telegraph publish. `from_config(config)` iterates `EFFORT_KEY_BY_PROVIDER.values()` so the per-provider effort key (`openai_reasoning_effort` / `anthropic_effort` / `google_thinking_level`) resolves without the dataclass knowing the mapping. Invariant #1 (root) lists the edits needed when adding a knob. Hashability via `frozen=True` is kept so a future re-introduction of multi-config support can re-collapse `_graph_pool` to a dict keyed on this without dataclass changes.
- **Graph pool.** `analysis.py:_graph_pool` is a single lazy `GraphPool` (built once on first acquire via double-checked locking under `_pool_mutex`), holding up to `Config.MAX_CONCURRENT_ANALYSES` `TradingAgentsGraph` instances bound to the active env config. `pool.acquire()` returns the first free one (or builds a new one outside the mutex if under cap, or blocks on `queue.Queue.get()` if at cap — but the cap matches the global asyncio semaphore so the blocking branch is unreachable). Each instance is single-use-at-a-time because the graph mutates `self.ticker / self.curr_state` during `propagate()`, but the pool gives us both parallelism (different instances run concurrently) and caching (instances are returned to the pool on completion). Don't bypass `_get_or_create_pool`. **No eviction** — the pool is process-lifetime; restart to apply `.env` changes.
- **Per-step progress + cooperative cancel.** `progress.py:delegating_progress_callback` is a singleton `BaseCallbackHandler` attached to every graph via `callbacks=[...]` in the constructor. **`raise_error = True` on this class is load-bearing** (Invariant #2): LangChain's callback manager swallows handler exceptions by default, defeating our raise-to-cancel strategy. With it enabled, raising `CancelledByUserError` from `_dispatch` aborts the about-to-fire LLM call and bubbles up through langgraph → `propagate()` → `to_thread`. TradingAgents passes our callbacks into the LLM kwargs, so we receive `on_chat_model_start` / `on_llm_start` events — **not** `on_chain_start`. LangGraph propagates the surrounding node name as `metadata["langgraph_node"]` on every nested LLM call. Per-run target (`ProgressReporter`) lives in `threading.local()` set by `run_trading_analysis` around `propagate()`. `ProgressReporter.cancel_event: threading.Event` is checked in `_dispatch` BEFORE every step update; the reporter also re-attaches the ❌ Cancel keyboard on every caption edit (Telegram drops `reply_markup` if not re-sent on `editMessageCaption` — Invariant #3).
- **Same-day result cache.** `cache.py` is filesystem-backed, keyed on `(AnalysisConfigKey, ticker, date_iso)` — no `user_id`, so two users tapping the same ticker share results within a day (the bot is single-config via `.env` so `AnalysisConfigKey` is the same for every user), and a manual `/watch` + same-day digest fire only pay for one LLM run. Public API: `lookup` / `store` / `today_iso()`. Layout: `<TG_BOT_DATA_DIR>/result_cache/<key.slug()>/<TICKER>/<date>.json`. Atomic writes (tempfile + fsync + rename, same pattern as `JsonStorage._save`); tempfile is `unlink`'d on any write exception. Each entry persists `{final_state, signal, telegraph_url, generated_at}` — full `final_state` (not a slim shape) so future renderer changes don't require re-running every cached ticker. LangChain message objects in `final_state` aren't JSON-native; `cache._json_default()` coerces via `model_dump` → `dict` → `{__type__, content}` → `{__type__, repr}` (Invariant #6). **Cache-hygiene gate is built into `cache.store`**: a falsy `telegraph_url` is a no-op (logged + skipped) — caching a failed publish would trap the user replaying "Instant View unavailable" until midnight rollover. Lazy eviction: a fresh date for the same `(key, ticker)` sweeps stale-date siblings **after** the atomic write succeeds, so a mid-write failure can't orphan yesterday's still-valid entry.
- **`from_config` effort resolution is first-truthy-wins across providers (`config_key.py:75-78`, `analysis.py`).** Iterates `EFFORT_KEY_BY_PROVIDER.values()` in insertion order (`openai_reasoning_effort` → `anthropic_effort` → `google_thinking_level`) and returns the first key whose value is truthy. Post-env-overlay this is effectively safe: operators set at most one of `TRADINGAGENTS_OPENAI_REASONING_EFFORT` / `TRADINGAGENTS_ANTHROPIC_EFFORT` / `TRADINGAGENTS_GOOGLE_THINKING_LEVEL` matching their `TRADINGAGENTS_LLM_PROVIDER`. But setting two simultaneously (e.g., openai + anthropic both armed while `TRADINGAGENTS_LLM_PROVIDER=anthropic`) silently picks openai's value for the cache slug / pool key / caption — misattributes downstream. If a future provider's key is alphabetically before openai's in iteration, that becomes the new winner; register effort knobs in `EFFORT_KEY_BY_PROVIDER` deliberately.
- **`_json_default` per-object fallback is silent (`cache.py:105-114`).** The fallback chain `model_dump → dict → {__type__, content} → repr` catches all exceptions at each step and falls through. There's no per-object log when a pydantic model raises mid-`model_dump` — only the outer `cache.store` emits a warning if the entire `json.dump` raises. A partially-coerced `final_state` writes successfully but renders garbage on cache-hit. If diagnostics around cache reads ever get noisy, add per-fallback DEBUG logs first.
- **`ProgressReporter` is `threading.local`, set by `run_trading_analysis` around `propagate()` (`progress.py:50,195`).** If a langgraph node ever spawns a sub-thread (e.g. a tool node using `ThreadPoolExecutor`), the child has no `_current_reporter.value`, so `_dispatch` silently drops cancel checks on any LLM calls fired from it. Today no node does this, but tradingagents upgrades could change that; the symptom would be "Cancel doesn't stop the run for the duration of one node" without any error.
- **`cache.lookup` self-heals on corrupt JSON (`cache.py`).** On `JSONDecodeError` the corrupt file is renamed aside to `<date>.json.corrupt-<unix_ts>` before returning `None`, so the next same-day tap is a clean miss + fresh write. Mirrors the two-tier `JsonStorage._load` recovery in `storage/_base.py`. Other exception classes (`OSError` on read permissions, transient disk error) log + return `None` but do NOT rename — the file might still be valid on retry. Backups are never auto-cleaned; operators sweep `data/result_cache/**/*.corrupt-*` manually, same convention as the storage layer's `.corrupt-*` backups. Pinned by `test_corrupt_file_is_self_healed` in `tests/test_cache.py`.
- **`_try_acquire_nonblocking` lives in `handlers/analysis_runner.py`, NOT pipeline.** Root CLAUDE.md "Known limitations" mentions it — that helper reads `sem._value` / `sem._waiters` private attributes for instant-reject of full-semaphore acquires. It's not a pipeline concern; documented here to redirect future searches.
